# Publishing DAIMO with Ontoology

This note describes how to publish the curated DAIMO repository with Ontoology using the current namespace first, and only later perform a controlled namespace migration if that is still required.

## Verified Ontoology constraints

According to the Ontoology homepage as checked on April 4, 2026:

- Ontoology expects repositories in the form `user/repository`.
- GitHub repositories inside organizations are reported as not currently supported.
- Ontoology can process OWL and RDFS vocabularies serialized in Turtle and RDF/XML.
- After repository authorization, Ontoology creates a pull request with generated documentation, diagrams, and evaluation artifacts.

Source:

- <https://ontoology.linkeddata.es/>

## Publication strategy for DAIMO

The sound publication sequence for this repository is:

1. Publish the current ontology repository in a public personal GitHub repository without changing the current namespace.
2. Run Ontoology on that stable version and confirm that documentation, diagrams, and validation artifacts are generated without errors.
3. Only after that, decide whether the namespace should remain at PURL or migrate to a different persistent identifier.

This order matters because it separates two different kinds of risk:

- repository and Ontoology publication issues
- namespace migration issues

If both are changed at the same time, it becomes much harder to identify the source of failures.

## Current namespace used in Phase 1

The repository is currently prepared to publish the ontology with:

`http://purl.org/pionera/daimo#`

For the first public Ontoology run, that namespace should remain unchanged.

## What Ontoology does and does not do

Ontoology is a publication and documentation automation service. It generates documentation pages, diagrams, and evaluation artifacts from the GitHub repository.

Ontoology does not mean that the ontology namespace must become an `ontoology.linkeddata.es` URL.

If a different long-term namespace is later required, the technically appropriate target is another persistent identifier, ideally a `w3id` namespace, not the Ontoology documentation URL itself.

## Phase 1 checklist

Before pushing the repository to GitHub:

- make sure the repository is public-ready
- keep the current PURL namespace unchanged
- keep the ontology in Turtle in the default branch
- keep the root `README.md` complete and readable
- make sure the ontology metadata includes title, description, creators, version information, and preferred namespace annotations
- run `python scripts/validate.py`
- choose and add the final repository license

Once the repository is public:

1. Go to <https://ontoology.linkeddata.es/>.
2. Submit the repository as `user/repository`.
3. Authorize Ontoology if requested.
4. Wait for Ontoology to analyze the repository.
5. Review the pull request generated by Ontoology.
6. Merge the pull request only after confirming that the generated documentation and validation outputs are correct.

## Expected result of Phase 1

After a successful Phase 1 publication:

- the ontology will be publicly visible in GitHub
- Ontoology will have generated browsable documentation and diagrams
- validation and publication artifacts will already exist for the current namespace
- the repository will be in a stable state for any later namespace migration
